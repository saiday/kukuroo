Self-hosted web push,
aimed at your iPhone.

A push endpoint you own, in one Cloudflare Worker: your keys, your origin, your lock screen. It exists for two reasons.

  • Notifications that come with something to do next should not be folded into a Telegram channel or a Discord server, fighting group chat for the same badge. Email is where they go to die.
  • And the other way to get one line onto a lock screen is to build, sign, and ship a native app whose entire job is that one line.

It runs on a Cloudflare Worker you deploy once. For one person's notifications, the free plan is plenty.

Kukuroo is a Cloudflare Worker plus KV. Deploy it once; there is no host, no TLS to renew, no process to babysit at 3am. On the free plan, personal use never gets near the meter.

No company in the middle.

Your keys live in your Worker, and the message is encrypted to your device. Nobody's dashboard ever sees your alerts.

No app to build.

Your phone has rendered these natively since iOS 18.4. No App Store, no $99 a year for four words on a lock screen.

The whole integration

# from cron, CI, a Raspberry Pi, your backend, a shell alias curl -X POST https://push.example.com/push/send \ -H "authorization: Bearer $KUKUROO_SEND_TOKEN" \ -d '{"notification":{"title":"Task W13 finished", "body":"W14 is unblocked and ready to start", "navigate":"https://push.example.com/"}}' {"delivered":1,"removed":0,"failures":[]}

That is not the quick start. That is the entire integration: anything that can make an HTTP call can ring your phone.

Standalone

Deploy your Worker

Copy the template, pick the hostname it will answer on, generate your keys with one command, deploy. Storage provisions itself.

npm install kukuroo cp -r node_modules/kukuroo/templates/standalone my-kukuroo cd my-kukuroo && npm install npx kukuroo init npx wrangler deploy
Put it on your Home Screen

Open your new page in Safari, Add to Home Screen, open it from the icon, type the invite code. Thirty seconds, once per device. That is Apple's one rule, and the only manual step in the whole thing.

POST when something happens

Drop the curl above into whatever should be able to reach you. The response tells you exactly how many devices it reached.

Mounted into a Worker you already have

Hand it your requests first

handle returns null for anything outside its prefix, so your own routing is untouched.

import { mountKukuroo } from "kukuroo"; const kukuroo = mountKukuroo({ prefix: "/push" }); export default { async fetch(request, env) { const hit = await kukuroo.handle(request, env); return hit ?? yourExistingRouter(request, env); }, };
Bind KV, then generate the keys

The binding name is fixed; the namespace itself provisions on your next deploy. Same one-command setup as standalone.

// wrangler.jsonc "kv_namespaces": [{ "binding": "KUKUROO_SUBS" }] # then npm install kukuroo && npx kukuroo init
Serve enrolment on your origin

Return the bundled page from any route of yours, or build your own against /push/subscribe. Devices then enrol on your site's hostname, which is where a notification tap should land.

import { enrolmentPage } from "kukuroo"; return new Response(enrolmentPage({ subscribePath: "/push/subscribe", publicKeyPath: "/push/public-key", }), { headers: { "content-type": "text/html" } });

Prerequisites

Kukuroo is opinionated, and the list of things it supports is short on purpose. All of it, before you install anything:

  • Cloudflare Workers. The only place it runs. No Docker image, no binary, no other host, and nothing to keep alive.
  • Safari. Declarative Web Push has not shipped anywhere else yet: no Chrome, no Firefox, no Android. Unsupported browsers are turned away at the enrolment page rather than left half working.
  • iOS 18.4 or later, with the page added to your Home Screen and opened from the icon. A Safari tab will not do, and that is Apple's rule rather than ours. macOS Safari 18.5 receives too, if you can think of a reason to want notifications on the machine you are already staring at.
  • About 50 devices per send on Cloudflare's free plan, which is the subrequest ceiling and roughly 47 more phones than one person owns. The README does the arithmetic.
